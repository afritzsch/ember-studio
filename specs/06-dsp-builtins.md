# 06 — Built-in DSP Processors

**Depends on:** 02 (Node API), 03 (TransportBlock for clip players/sampler) · **Owns:** `Sources/DAWEngine/dsp/`, `Sources/DAWEngine/nodes/`.

All processors are `daw::Node` subclasses, stereo in/out, with parameters through ParamSlots smoothed per block (ENG-022). Each has a **parameter table** (id, name, range, default, unit, curve) exported as JSON for the model and UI (`ParamInfo`).

## Requirements

#### Overlapping clips: "later clip wins" (clarified in T-035)
- **Order.** A player orders its clips by `(start, clipID)`, the model's track order (MODEL-005, DW-110); it sorts them itself, so the order of `ClipDesc`s in a GraphDescription doesn't matter. "Later" means later in this order: a later start wins, and for equal starts the larger `clipID` wins. Clips are placed in samples as in DSP-001; a clip *covers* the samples `[S, E)` = `[tickToSample(start), tickToSample(start + length))`.
- **Who sounds.** On every sample the latest clip covering it wins and the clips under it are silent, except inside the crossfades below. So a clip fully inside another wins over its whole length and the outer clip resumes after it. With equal starts the later one sounds from its first sample (the other hasn't sounded yet, so there is nothing to fade from), and an earlier clip that also ends no later is never heard.
- **Crossfades at both boundaries.** A clip `c` fades in over another clip at its start if an earlier clip with a *strictly earlier start tick* still covers `S`. Let `U` be the largest end sample of those clips; the fade-in lasts `nIn = min(64, U − S, E − S)` samples, so it is complete before the clip underneath ends. A clip fades out over another at its end if any earlier clip (equal starts included) ends after it in samples; the fade-out lasts `nOut = min(64, E − S)`. Both crossfades lie inside `c`'s own span, where the audio of the clip underneath exists. A clip that starts or ends with nothing underneath (silence, an adjacent clip) gets no crossfade; DSP-001 is unchanged there.
- **Equal-power curve.** At distance `d` from the boundary inside `c` (`d = p − S` for the fade-in, `d = E − 1 − p` for the fade-out) the fraction is `f = (d + 1)/n` for `d < n`, else 1; where both apply, the smaller `f` counts. `c` plays at `sin(f·π/2)` and passes `cos(f·π/2)` to the clips under it, so the two weights' squares sum to 1. A boundary's first sample inside `c` plays it at `sin(π/(2n))`, and the frame after the fade-in has it at 1 and the clip underneath at 0. With more than two layers each clip's weight is its own `sin` times the `cos` of every later clip covering the sample.
- **What doesn't change the geometry.** Clip gain and the linear fades of DSP-001 shape a clip's own audio only: a faded-out winner leaves a gap and doesn't reveal the clip underneath. Coverage depends only on the clips, not on their assets: a clip whose asset is missing, at the wrong rate or shorter than the clip still hides what is under it (with silence, as in DSP-001). Loop-wrap crossfades (TIME-005/006) apply on top, to the whole player output.

#### MidiClipPlayer semantics (clarified in T-040)
- A note's on sounds at `tickToSample(start)` and its off at `tickToSample(start + length)`. Within a block, events are in frame order, and offs come before ons on the same tick. Notes are fixed per instance (DW-051, like DSP-001). Notes with length ≤ 0, pitch > 127 or channel > 15 are dropped, and velocity is clamped to 1..127.
- Notes are chased (user decision, DW-103, T-041): playback that starts inside a note (play, locate, loop start, or a tempo edit that moved the playhead's tick) sounds it from that frame, for its remaining length. On every segment that doesn't continue the previous one, after the hanging notes' offs, each note with `start < startTick` whose `tickToSample(start + length)` is after the segment's first sample gets its on at the segment's first frame (in note-start order), under the same capacity rule as any other on.
- "Hanging notes" are the notes the player has started and not yet ended. Each gets exactly one note-off (velocity 64): at its end; at the first frame of a segment that doesn't continue the previous one's ticks (loop wrap, locate, or a tempo edit that moved the playhead's tick), before that segment's ons; or at frame 0 of a stopped block. The offs are explicit per note, not CC 123.
- A new instance can't know what the instance it replaces left on, so its first non-empty block starts with All Notes Off (CC 123) on all 16 channels.
- `midiOut` has fixed capacity. A note-on is written only if room stays for its own off and the offs of all held notes, so a full writer drops notes and never leaves one hanging.

#### Sampler semantics (clarified in T-041)
- **Zones (DSP-020)** come from the node's `configJSON` and are fixed per instance (DW-051): the model bumps `configVersion` when they change or an asset they use finishes loading. Format: `{"zones": [{"assetID": 7, "rootKey": 69, "lowKey": 0, "highKey": 127, "lowVel": 1, "highVel": 127, "tune": 0, "gain": 1, "loopStart": 0, "loopEnd": 48000}]}`. Only `assetID` is required; defaults are rootKey 60, the full key and velocity ranges, tune 0 (semitones), gain 1 (linear) and no loop. Loop points are source frames, `[loopStart, loopEnd)`, both or neither; a loop is clamped to the asset and dropped if that leaves it empty. An empty string or `{}` is a sampler without zones; unknown keys are ignored; malformed JSON or out-of-range values are `invalidArgument`. A zone whose asset isn't loaded or isn't at the session rate is silent.
- A note-on starts one voice per playable zone whose key and velocity ranges (inclusive) contain it, so zones layer. Voices read from frame 0; one-shot voices end at the asset's end, looping ones wrap until their release ends. Velocity `v` scales the zone gain by `(1 − s) + s·(v/127)²`, `s` the velocity-sensitivity param.
- **Voices (DSP-022):** at most 32 sound. A note-on beyond that steals the oldest note, preferring notes already released (not held by key or pedal); the stolen voice fades out linearly over 5 ms in one of 32 extra fade slots while the new note starts at once. If all fade slots are busy too, the quietest fade is cut.
- **ADSR (DSP-022):** linear segments advanced per sample; MIDI events act on their exact frame. Params (relative to `firstParam`, read once per block): 0 attack 0…10 s (default 0.002), 1 decay 0…10 s (0.3), 2 sustain 0…1 (1), 3 release 0…20 s (0.2), 4 velocity sensitivity 0…1 (1). Params beyond `numParams` use their defaults.
- **MIDI (DSP-023, DW-100):** per channel. Note-off (or note-on velocity 0) releases the oldest held note on that key, all its layers. CC 64 ≥ 64 is pedal down: note-offs are deferred until it goes up. CC 123 (All Notes Off) is a note-off for every held note on the channel, so the pedal still holds them (MIDI 1.0). Pitch bend is ±2 semitones (8192 centre, both ends exact), applied from its frame on. Other messages are ignored.

#### Compressor semantics (clarified in T-071)
- **Params (DSP-031, DSP-041)**, relative to `firstParam`, read once per block; slots beyond `numParams` use their defaults, NaN reads as the default, other values are clamped: 0 threshold −60…0 dB (default −20), 1 ratio 1…20 (4), 2 attack 0.1…200 ms (10), 3 release 1…2000 ms (100), 4 knee 0…24 dB full width (6), 5 makeup 0…24 dB (0), 6 detector switch, RMS at ≥ 0.5, else peak (0). Threshold, ratio, knee and makeup ramp linearly across the block (ENG-022); attack, release and the detector are latched per block. The table is published through the facade's `paramInfoJSON` (`NodeRegistry::paramInfo` doesn't exist yet, see the T-071 report).
- **Key (MIX-008).** The detector reads the sidechain input when one is routed (`NodeIO::sidechain` non-empty), else the node's own input. Stereo-linked: every key channel counts and one gain applies to all channels.
- **Signal path**, per sample, in double: level `x` = 20·log10(max over channels |key|) (peak) or 10·log10(m) with `m[n] = β·m[n−1] + (1−β)·mean(key²)`, `β = exp(−1/(10 ms · rate))` (RMS), floored at −200 dB. Gain computer: the log-domain curve with a quadratic soft knee (Giannoulis et al. 2012): `c = 0` for `2(x−T) ≤ −W`, `(1/R − 1)(x − T + W/2)²/(2W)` inside the knee, `(1/R − 1)(x − T)` above it. Ballistics: `e[n] = α·e[n−1] + (1−α)·c` with `α = exp(−1/(t · rate))`, `t` = attack when `c < e[n−1]`, else release. Output: `in · 10^((e + makeup)/20)`. `e` and `m` snap to exactly 0 near it, so silence settles to unity gain without denormals. No lookahead: latency 0.
- **Gain-reduction meter.** The kind meters (`NodeKindInfo::meters`), so GraphBuilder gives it a MeterID and the facade's `meter(node)` reads it. Each block writes linear gain factors without makeup (1 = no reduction): `peak` is the block's deepest reduction (smallest factor), `rms` the factor at its last frame.
- **NaN guard (DSP-040).** A block whose input or key holds NaN/±Inf outputs silence and restarts the detector (`e = m = 0`); the node counts it (`nanBlocks()`), since Telemetry has no processor NaN counter yet (DW-142).
- `reset()` (locate) keeps the envelope, like other effects (TIME-008).

#### Reverb semantics (clarified in T-073)
- **Params (DSP-033, DSP-041)**, relative to `firstParam`, read once per block; slots beyond `numParams` use their defaults, NaN reads as the default, other values are clamped: 0 size 0…1 (default 0.5), 1 decay 0.1…20 s, log (2; the RT60 at low frequencies), 2 damping 0…1 (0.5), 3 pre-delay 0…200 ms (10), 4 mix 0…1 (0.3; 0 dry only, 1 wet only). All automatable. Decay and mix ramp linearly across the block (ENG-022). Size and pre-delay move delay times, so instead of stepping (a click) each delay time glides to its new whole-frame value at 1/8 frame per frame (a short pitch bend, read with linear interpolation). Damping is latched per block. The table is published through the facade's `paramInfoJSON` (like the compressor's, DW-173).
- **Network.** A feedback delay network of 8 lines mixed by the orthogonal matrix `H8/√8` (Sylvester Hadamard, entry `(−1)^popcount(r & c)`), so the mixing is lossless and the decay comes from the line gains alone. Line `i` is `Lᵢ = max(1, round(Bᵢ · s · rate / 48000))` frames with `B = {2411, 2647, 2953, 3203, 3541, 3833, 4241, 4799}` (≈ 50…100 ms at size 1) and `s = 0.15 + 0.85 · size`.
- **Signal path**, per sample, in float: the input (left = channel 0, right = channel 1, or channel 0 again for a mono input; no input is silence, and the tail rings on) is delayed by the pre-delay `P = round(ms · rate / 1000)` frames (0 is the current frame). Each line output `xᵢ` (read before this frame's write) goes through a one-pole lowpass `zᵢ = (1 − a)·xᵢ + a·zᵢ`, `a = exp(−2π·f/rate)`, `f = min(18000 · (500/18000)^damping, 0.45·rate)` Hz, and the gain `gᵢ = 10^(−3·Lᵢ/(decay·rate))` (60 dB per `decay` seconds per pass; from the target lengths, so a glide doesn't change the decay). Then `m = H8·(g·z)/√8`, and line `i` gets `mᵢ` plus the pre-delayed left input (even `i`) or right input (odd `i`). Wet outputs: `wL = ¼ Σ (H8 row 1)ᵢ xᵢ`, `wR = ¼ Σ (H8 row 2)ᵢ xᵢ` (orthogonal taps, so L and R are decorrelated). Output `(1 − mix)·dry + mix·wet` per channel; channels beyond stereo are silent. An impulse's first wet sample is at `P + L₀`.
- **Determinism (IO-011).** No modulation, noise or random state: the same input and params give the same bits for any block sizes (ENG-004). `reset()` (locate) keeps the tail, like other effects (TIME-008); two renders on one engine therefore differ by the first one's leftover tail (DW-063), and the golden `reverb_determinism` compares renders on fresh engines.
- **Silence (DSP-040).** A value written to a line or held in a damping filter below 1e-9 (−180 dBFS) is stored as exactly 0, so after the input stops the output reaches exact 0 in finite time (about `decay · 3` s after a 0 dBFS input) and nothing decays into denormals. The Node API has no tail length; an export's tail (IO-012) ends on quiet output, and the tail falls by 60 dB per `decay` seconds.
- **NaN guard (DSP-040).** A block whose input holds NaN/±Inf outputs silence and clears the network (lines, pre-delay, filters); the node counts it (`nanBlocks()`), since Telemetry has no processor NaN counter yet (DW-142).
- **Memory.** `prepare()` allocates the lines for size 1 and the 200 ms pre-delay at the session rate; `process()` never allocates. Latency 0: the pre-delay is part of the effect, not reported for PDC.

#### Delay semantics (clarified in T-072)
- **Params (DSP-032, DSP-041)**, relative to `firstParam`, read once per block; slots beyond `numParams` use their defaults, NaN reads as the default, other values are clamped: 0 time 1…4000 ms, log (default 375; used while sync is off), 1 sync switch, on at ≥ 0.5 (1), 2 note 0…13 (5 = 1/8; rounded to the nearest index), 3 feedback 0…0.95 (0.35), 4 lowpass 200…20000 Hz, log (8000; 20000 is off), 5 ping-pong switch, on at ≥ 0.5 (0), 6 mix 0…1 (0.3; 0 dry only, 1 wet only). All automatable. Feedback and mix ramp linearly across the block (ENG-022); lowpass and ping-pong are latched per block. The table is published through the facade's `paramInfoJSON` (like the compressor's, DW-173).
- **Note values**, shortest first, in quarter notes: 1/32 (⅛), 1/16T (⅙), 1/16 (¼), 1/8T (⅓), 1/16D (⅜), 1/8 (½), 1/4T (⅔), 1/8D (¾), 1/4 (1), 1/2T (4⁄3), 1/4D (1.5), 1/2 (2), 1/2D (3), 1/1 (4).
- **Delay time** `T` in whole frames: `round(time · rate / 1000)` with sync off, `round(beats · 60 · rate / bpm)` with sync on, where `bpm` is the tempo at the block's start (`tempoAtStart`, TIME-007; also while stopped, from the playhead's position; 120 without a tempo map). Then clamped to 1 … `round(4 s · rate)`, so long notes at slow tempos stop at 4 s. At 120 bpm and 48 kHz a 1/8 note is 12000 frames (250 ms).
- **Time changes** (a param, sync, the note or the tempo) don't move the read tap, which would click, or glide it, which would bend the pitch: the output crossfades linearly from the tap at the old `T` to the tap at the new one over 20 ms (`N = round(0.02 · rate)` frames; frame `k` = 1…N of it weights the new tap `k/N`). A `T` that changes again during a crossfade is taken up when it ends. Lengthening the time reads part of the line again (like a tape delay whose head moves back), so echoes already in flight can sound once more; shortening skips part of it.
- **Signal path**, per sample, in float: inputs `inL` = channel 0, `inR` = channel 1 (or channel 0 again for a mono input; no input is silence, and the echoes ring on). Taps `x_c` = line `c` read `T` frames back (before this frame's write). Loop lowpass `z_c = (1 − a)·x_c + a·z_c`, `a = exp(−2π·f/rate)`, `f = min(lowpass, 0.45·rate)`, or `z_c = x_c` at 20000 Hz. Writes, stereo: `line_L ← inL + fb·z_L`, `line_R ← inR + fb·z_R`; ping-pong: `line_L ← ½(inL + inR) + fb·z_R`, `line_R ← fb·z_L`, so the input enters on the left and the echoes alternate left (at `T`), right (`2T`), left … Output `(1 − mix)·in_c + mix·x_c`; channels beyond stereo are silent. The first echo is the input unfiltered; each further repeat has passed the lowpass once more and is `fb` times quieter.
- **Silence (DSP-040).** A value written to a line or held in a lowpass below 1e-9 (−180 dBFS) is stored as exactly 0, and feedback is < 1, so after the input stops the output reaches exact 0 in finite time and nothing decays into denormals. The Node API has no tail length; an export's tail (IO-012) ends on quiet output.
- **NaN guard (DSP-040).** A block whose input holds NaN/±Inf outputs silence and clears the lines and filters; the node counts it (`nanBlocks()`), since Telemetry has no processor NaN counter yet (DW-142).
- **Memory, latency, locate.** `prepare()` allocates 4 s per channel at the session rate; `process()` never allocates. Latency 0. `reset()` (locate) keeps the echoes, like other effects (TIME-008, DW-162). The same input and params give the same bits for any block sizes (ENG-004).

#### EQ semantics (clarified in T-070)
- **Params (DSP-030, DSP-041)**, relative to `firstParam`, read once per block; slots beyond `numParams` use their defaults, NaN reads as the default, other values are clamped. Six bands: 0 HP on, 1 HP frequency, 2 HP Q; 3 low shelf on, 4 frequency, 5 gain, 6 Q; 7 peak 1 on, 8 frequency, 9 gain, 10 Q; 11 peak 2 on, 12 frequency, 13 gain, 14 Q; 15 high shelf on, 16 frequency, 17 gain, 18 Q; 19 LP on, 20 frequency, 21 Q. Frequencies 20…20000 Hz, log; gains −24…24 dB, linear; Q 0.1…10, log. Defaults: HP off at 30 Hz, low on at 100 Hz, peak 1 on at 400 Hz, peak 2 on at 2500 Hz, high on at 8000 Hz, LP off at 20000 Hz; every gain 0; shelf, HP and LP Q 0.7071, peak Q 1. A switch is on at ≥ 0.5. Frequencies are capped at 0.49 · rate, which only matters below 44.1 kHz. All frequencies, gains and Qs are automatable; the switches aren't. The table is published through `NodeRegistry::paramInfo` (DSP-041), which `paramInfoJSON` reads for every kind.
- **Signal path**, per sample, in double: HP → low shelf → peak 1 → peak 2 → high shelf → LP, RBJ cookbook biquads (`dsp/Biquad.h`), each a TDF-II section with its own state per channel. Inputs: left = channel 0, right = channel 1 (or channel 0 again for a mono input; no input is silence, and the filters ring on). Channels beyond stereo are silent. Latency 0.
- **Flat.** A band that is off, or on at 0 dB, is `H(z) = 1` and passes its input bit for bit, so the default EQ is exactly flat. (A peak or shelf at 0 dB has identical numerator and denominator doubles, so its state stays exactly 0.)
- **Coefficient changes (DSP-030).** Coefficients are recomputed once per block, only when a band's params changed, and the band moves to them linearly across that block (coefficient by coefficient, the ENG-022 ramp shape, exact at the last frame), carrying the TDF-II state. The set of stable biquads is convex in `(a1, a2)`, so every interpolated filter is stable. A large step in one small block is as abrupt as the block (bounded, no blow-up; the model or automation smooths faster moves over many blocks). The first block after `prepare()` jumps.
- **Silence (DSP-040).** When both TDF-II state terms of a section are below 1e-12 (−240 dBFS) they are stored as exactly 0, so after the input stops the output reaches exact 0 in finite time and nothing decays into denormals. Both together: the two terms nearly cancel in a narrow low-frequency filter, and zeroing one alone re-excites it (a limit cycle around 1e-9).
- **NaN guard (DSP-040).** A block whose input holds NaN/±Inf, or whose output went non-finite, outputs silence and clears the filter state; it counts in `nanBlocks()` and the `nanBlocks` telemetry counter. Since T-070 the compressor, reverb and delay guards count there too (DW-142).
- `reset()` (locate) keeps the filter state, like other effects (TIME-008). `process()` never allocates; the same input and params give the same bits for any block sizes (ENG-004).

                   enum class Curve { linear, log, db } curve; const char* unit; bool automatable; };

                     static std::unique_ptr<Node> create(NodeKind, std::string_view configJSON); };
